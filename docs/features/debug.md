# 排障与调试

录制出问题时，本页列出的开关可以拿到两类信息：**底层工具（ffmpeg / mesio / 录播姬）的日志**，以及**平台下发的原始报文**。

这些开关**默认全部关闭**，产物写在视频同目录，且**不会被自动清理**（详见文末）。排查完请记得关掉开关并手动删除文件。

## 调试模式（`debugLevel`）

位置：设置 → 录制 → **调试模式**（下拉框）；也可以在「录制工具 → 添加/编辑直播间」里按房间单独设置（右侧可勾选「全局」跟随）。

| 档位 | 写 `<视频名>_<录制器ID>.recorder.log` | 底层工具日志级别 |
| ---- | ------------------------------------- | ---------------- |
| 关闭 | 否                                    | 默认             |
| 基础 | 是                                    | 默认             |
| 详细 | 是                                    | 打开 debug 级别  |

- **基础与详细在"是否落盘"上完全一样**，唯一差别是「详细」会把底层工具自己的调试输出打开
  （ffmpeg `-loglevel debug`、mesio `-v`、录播姬 `-l Debug`），文件体积随之大一个量级。
- 落盘位置：`<视频文件名>_<录制器ID>.recorder.log`，与视频同目录，**每场录制一个**。
- 与开关无关、始终写入应用日志的内容：弹幕连接状态（open / close / reconnect）、录制结束原因等。
  ffmpeg 的 stderr 不进应用日志（避免刷屏），只有开启调试模式后才写进 `.recorder.log`。

::: tip 该选哪一档
先选**基础**：能拿到 ffmpeg 默认级别的错误/警告与弹幕连接状态，体积可控。
只有当需要看 HTTP 请求、逐包细节时才选**详细**。
:::

::: warning `debugMode` 已废弃
老配置里可能还有 `debugMode: true/false` 这个布尔字段，**代码已不再读取它**，仅保留用于兼容旧配置。
真正生效的是 `debugLevel`。
:::

## 四路原始报文转储

仅抖音支持（这四类消息都走抖音的弹幕通道）。

| 开关                      | 界面位置                  | 产物文件                  | 体量（实测量级）           | 主要用途                                |
| ------------------------- | ------------------------- | ------------------------- | -------------------------- | --------------------------------------- |
| PK 原始报文（`rawLogPk`） | 设置 → 录制 → 抖音 → 调试 | `<视频名>_pk_raw.jsonl`   | 单场几百 KB                | 昵称补齐所需的 `userInfos`、PK 场次标识 |
| 在线人数（`rawLogRoom`）  | 同上                      | `<视频名>_room_raw.jsonl` | 约 5700 条/小时            | 核对 `displayValue` 与 `total` 的口径   |
| 贡献榜（`rawLogRank`）    | 同上                      | `<视频名>_rank_raw.jsonl` | 约 1800 条/小时            | 榜单顺序、头像字段                      |
| 礼物（`rawLogGift`）      | 同上                      | `<视频名>_gift_raw.jsonl` | 单行约 2 KB，单场可达数 MB | 礼物图标字段、同名多图问题              |

- **默认关闭**，关闭时不创建任何文件；首条消息到来时才创建文件。
- 同一场录制重跑会**覆盖写**，不保留上一次的数据。
- 每行格式：`{"tag":"<消息类型>","at":<毫秒时间戳>,"payload":{…}}`，一行一条，便于 `grep` / `jq` 过滤。

::: tip 前置条件
四个开关只在「弹幕录制」开启时可用 —— 关闭弹幕录制后弹幕通道不连接，自然不会有原始报文。
:::

### 两种开启方式（取或）

| 方式       | 做法                                                                    | 适用场景                                                          |
| ---------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 设置页开关 | 勾选上表中对应开关                                                      | 打包版（从桌面/开始菜单启动）；改完对**下一场**录制生效，无需重启 |
| 环境变量   | 启动程序前设置 `BILILIVE_TOOLS_PK_RAW_LOG=1`（ROOM / RANK / GIFT 同理） | 命令行开发、一次性取证                                            |

两者是**取或**关系：任一为真即开启。环境变量只能"打开"，不能把设置页已开的开关关掉。

| shell      | 命令                                   |
| ---------- | -------------------------------------- |
| Nushell    | `$env.BILILIVE_TOOLS_PK_RAW_LOG = "1"` |
| PowerShell | `$env:BILILIVE_TOOLS_PK_RAW_LOG = "1"` |
| cmd        | `set BILILIVE_TOOLS_PK_RAW_LOG=1`      |
| bash       | `export BILILIVE_TOOLS_PK_RAW_LOG=1`   |

::: warning 打包版读不到 shell 的环境变量
从图形界面启动的应用**不会继承**你在终端里 `export` 的变量 —— 这是"设了变量却没有产物"的最常见原因。
遇到这种情况请改用**设置页开关**。
:::

::: tip 怎么确认"到底开没开"
四路全关时，每场录制开始时应用日志会打印一行：

```
[rawLog] 四路原始报文转储均未启用（设置页「调试」四项均关，BILILIVE_TOOLS_{PK,ROOM,RANK,GIFT}_RAW_LOG 亦非 "1"）
```

开启后则会打印 `[pkRawLog] 转储已启用 → <文件路径>`（首次落盘时）。
:::

## 产物在哪儿、怎么清理

- 两类产物都在**视频同目录**：
  - `<视频名>_<pk|room|rank|gift>_raw.jsonl`
  - `<视频名>_<录制器ID>.recorder.log`
- 它们**不会被同步、也不会随视频一起删除** —— 文件同步与删除逻辑只处理视频、弹幕、XML、封面这四类。
  因此长期开着开关会在视频目录里持续堆积文件，需要**手动删除**。
- 分段录制时，转储文件名会带上 ffmpeg 的字面量占位符（例如 `<视频名>-PART%03d.flv_pk_raw.jsonl`），
  仍然**每场录制只有一个**，不随分段切割。

## 应用日志在哪

应用自身日志（含上面那些 `[rawLog]` 行）写在用户数据目录的 `logs` 子目录，启动时会在日志开头打印实际路径，例如：

```
日志路径: C:\Users\<用户名>\AppData\Roaming\biliLive-tools\logs
```

各平台的具体位置见[安装](/guide/installation)。
