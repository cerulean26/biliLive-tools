# 抖音礼物图标与头像

录制抖音直播时，礼物消息里的**礼物图标**与**送礼者头像**会随弹幕 XML 一并保存，可在浏览器预览里直接看到图片。

::: tip 适用范围
仅抖音支持。图标/头像只在有数据时才写入，其他平台不会留下空属性。
:::

## 数据写在哪儿

与弹幕同目录、同一个文件：`<视频文件名>.xml`。

图片地址只存**相对路径**（如 `webcast/5ddf….png`），不存完整 URL —— CDN 域名与模板参数会轮换，存相对路径才不会随域名变更而失效。拼接规则见[「如何拼出完整 URL」](#如何拼出完整-url)。

### `<gi>`：礼物图标表

```xml
<gi i="6937" n="点亮粉丝团" u="webcast/5ddfcd51beaa7cad1294a4e517bc80fb.png"/>
<gi i="6938" n="点亮粉丝团" u="webcast/d4006cb1beaa7cad1294a4e517bc80fb.png"/>
```

| 属性 | 含义                |
| ---- | ------------------- |
| `i`  | 礼物 ID（查表的键） |
| `n`  | 礼物名              |
| `u`  | 图标相对路径        |

**为什么按礼物 ID 建表而不是按礼物名**：礼物名**不是**唯一标识 —— 实测「点亮粉丝团」同时对应 giftId `6937` 与 `6938`，且两者图标不同。按名字建表会让其中一部分礼物显示成错误的图。

因此每条 `<gift>` 上都带 `giftid`，预览时靠它查表：

```xml
<gift ts="0.5" giftname="点亮粉丝团" giftid="6937" giftcount="1" price="1000" user="甲" uid="334723570733996"/>
```

### `<ui>`：用户头像表

```xml
<ui i="334723570733996" p="100x100/aweme-avatar/tos-cn-abc"/>
```

| 属性 | 含义                                                |
| ---- | --------------------------------------------------- |
| `i`  | 用户 uid（`<gift>` 上本来就有 `uid`，无需额外属性） |
| `p`  | 头像相对路径                                        |

`uid → 头像` 实测严格 1:1，uid 天然就是正确的键。

### 为什么是「首见声明」而不是逐条写

一条礼物消息的图片地址约 145 字符，而一场直播往往只有几十种礼物、几百位用户。逐条写会把文件撑大数倍：

| 样本 | 礼物条数 | 逐条写            | 建表后               |
| ---- | -------- | ----------------- | -------------------- |
| A 场 | 1017 条  | +141.5 KB（+97%） | **+46.7 KB（+32%）** |
| B 场 | 71 条    | +9.7 KB（+61%）   | **+3.6 KB（+22%）**  |

声明写在**该礼物/用户第一次出现的那批消息里**（就地），而不是像 `<pk_users>` 那样集中到文件末尾：体积相同，但录制异常中断时已写入的部分不会丢，流式解析也不需要读完整文件。

按「分段」录制时，每个分段各声明一次 —— 仍是按种类数而非条数计算。

## 网页预览

用 Chrome / Edge / Firefox 直接打开 XML 即可（文件内嵌 XSL 样式）。礼物表列为：

头像 / 用户名 / 用户ID / 图标 / 礼物名 / 礼物数量 / 出现时间

查不到图片时该单元格为空，**不会拼出无效地址**。

## 如何拼出完整 URL

抖音的图片有两类前缀，规则不同：

| 相对路径前缀 | 完整 URL                                                  |
| ------------ | --------------------------------------------------------- |
| `webcast/`   | `https://p3-webcast.douyinpic.com/img/<u>~tplv-obj.image` |
| 其他         | `https://p11.douyinpic.com/aweme/<u>.jpeg`                |

礼物图标实测全部是 `webcast/` 开头；头像多数是 `100x100/aweme-avatar/…`（走 `p11`），偶尔也会出现 `webcast/`，所以两类都要判断。

XSL 里的写法（已实测）：

```xml
<z:variable name="u" select="key('giById',@giftid)/@u"/>
<z:if test="string($u)">
  <z:choose>
    <z:when test="starts-with($u,'webcast/')">
      <img src="https://p3-webcast.douyinpic.com/img/{$u}~tplv-obj.image"/>
    </z:when>
    <z:otherwise>
      <img src="https://p11.douyinpic.com/aweme/{$u}.jpeg"/>
    </z:otherwise>
  </z:choose>
</z:if>
```

::: warning `test="string($u)"` 不能写成 `test="$u"`
表里可能存着空属性（`u=""`）。`<z:if test="$u">` 对**空的节点集**为 false，但对**值为空的字符串**为 true，会走进 `otherwise` 分支拼出 `…/aweme/.jpeg` 这样的无效地址。用 `string($u)` 取字符串值后再判断才正确。
:::

## 已知限制

1. **同名不同 ID 的礼物**：「点亮粉丝团」这类同名多 ID 的礼物靠 `giftid` 区分，能正确显示各自的图。
2. **上游数据本身不一致**：极少数 giftId 对应多个礼物名（实测 1 例，各 1 条），任何键都无法区分，按出现顺序取第一张图。
3. **头像只有送礼者才有**：头像数据只在礼物消息里下发，没送过礼物的用户不会有 `<ui>` 条目。
